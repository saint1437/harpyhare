# Встроенная панель превью + перекомпоновка HUD — дизайн

**Дата:** 2026-06-11
**Статус:** утверждён, готов к плану реализации

## Задача

Переделать раскладку HUD и заменить отдельное окно HTML-превью встроенной панелью:

1. Переименовать секцию «Диалог» → «Чат» и поднять её наверх (разговор сверху, композер снизу).
2. Убрать сворачивание секции чата — чат всегда виден; окно получает одну фиксированную высоту (без компакт/полный).
3. Удалить отдельное окно превью (фича от 2026-06-11) целиком; HTML-превью встроить в то же окно как панель справа, открывающуюся/закрывающуюся. Открытие = окно расширяется вправо (левый контент пиксельно неподвижен).
4. Увеличить высоту окна по умолчанию (точные числа — позже, в спеке стоят рабочие значения-заглушки).

## Решения (зафиксированы в брейншторме)

| Вопрос | Решение |
|---|---|
| Что значит «открепить» | Отказались от отдельных окон/пресетов. Превью — встроенная правая панель в том же окне |
| Раскладка | `StatusBar(табы)` → «Чат» (сверху) → `Composer` → `HotkeyHints` |
| Сворачивание чата | Убрать. Чат всегда виден, окно — одна фиксированная высота |
| Открытие превью | Окно расширяется **вправо** на ширину панели; левый край и левый контент неподвижны. Закрытие сужает обратно |
| Кламп | Если расширение выходит за правый край экрана — окно сдвигается влево, оставаясь целиком на мониторе |
| Отдельное окно превью | Удаляется полностью (Rust-команды, окно, capability, роутинг, PreviewApp, хук, событие) |
| JS в превью | Без изменений: `<iframe sandbox="allow-scripts">` без `allow-same-origin` |
| Высота по умолчанию | Увеличить; рабочее значение в спеке, финальные числа — позже |

## Текущее состояние (для контекста)

- `App.tsx`: `COMPACT_HEIGHT = 290` / `FULL_HEIGHT = 660`; состояние `answerOpen`; эффект `setWindowHeight(answerOpen ? FULL : COMPACT)`; авто-раскрытие при первом контенте; `AnswerPanel` с `expanded`/`onToggle`. Корень — `<div className="app-shell ... flex-col gap-3 ... rounded-[22px] p-4">`.
- `AnswerPanel.tsx`: шапка с кнопкой-тогглом «Диалог» (шеврон) + «Копировать»; `expanded` гейтит скролл-зону; рендер сообщений + `partial`; override `pre` → `HtmlBlockChip` через `onOpenPreview`.
- Превью-окно (удаляется): Rust `show_html_preview`/`get_preview_html`, state `preview_html`, конст. `PREVIEW_LOGICAL_HEIGHT`/`PREVIEW_GAP`, модуль `preview.rs` (`preview_rect`), `capabilities/preview.json`, роутинг `?window=preview` в `main.tsx`, `PreviewApp.tsx`, `usePreviewHtml.ts(.test)`, событие `preview-html`, ipc `showHtmlPreview`/`getPreviewHtml`/`closePreviewWindow` + `DEMO_PREVIEW_HTML`.
- Сохраняется: `extractHtmlBlocks` (`lib/html-blocks.ts`), `HtmlBlockChip`, override `pre`, настройка `auto_preview_html` (9-е поле Settings), sandbox-iframe.
- Окно `main`: transparent + decorations:false + alwaysOnTop; фон рисует `.app-shell` через `--app-opacity`. `tauri.conf.json` initial height синхронизирован с компактной высотой. Манипуляции размером окна — только Rust-командами (capability `set-size` для JS не выдана). `set_window_height` уже твинит (ease-out) с guard-генератором `resize_gen`.

## Часть 1 — Перекомпоновка и переименование

- В `App.tsx` изменить порядок рендера левой колонки: `StatusBar` → `AnswerPanel` (Чат) → `Composer` → `HotkeyHints`.
- `AnswerPanel`: убрать сворачивание — удалить пропсы `expanded`/`onToggle`, шеврон и кнопку-тоггл; заголовок секции — статичный «Чат» (тот же стиль: моно, аплеркейс, разделительная линия) + кнопка «Копировать» (как сейчас, видна когда есть ответ ассистента и не идёт стрим). Скролл-зона сообщений всегда видна; пустое состояние — «Чат появится здесь».
- Удалить из `App.tsx`: состояние `answerOpen`, эффект высоты по `answerOpen`, авто-раскрытие, эффект пересборки `answerOpen` при смене чата. Высота окна больше не зависит от чата.

## Часть 2 — Встроенная панель превью справа

**Структура корня.** `.app-shell` становится горизонтальным флекс-контейнером (`flex-row`, та же `rounded-[22px] p-4`, фон/опасность как сейчас): слева — колонка `flex-col gap-3 flex-1` со стеком из Части 1; справа — `PreviewPanel`, когда открыта. Левая колонка остаётся той же пиксельной ширины: окно расширяется ровно на футпринт панели (ширина панели + gap), поэтому `flex-1`-колонка визуально не меняется.

**Компонент `PreviewPanel`** (`src/components/PreviewPanel.tsx`, презентационный): шапка «Превью» + «Копировать код» (`navigator.clipboard.writeText(html)`) + ✕ (`onClose`); ниже — `<iframe sandbox="allow-scripts" srcDoc={html}>` (белый фон, скругление, без `allow-same-origin`). Пропсы `{ html: string; onClose: () => void }`.

**Состояние в `App.tsx`.** `previewHtml: string` и `previewOpen: boolean`. Открытие: `openPreview(code)` → `setPreviewHtml(code); setPreviewOpen(true)`. Закрытие: `setPreviewOpen(false)` (HTML можно не сбрасывать). Чип в «Чате» (`onOpenPreview`) и автооткрытие (`onAssistantDone` под гейтом `auto_preview_html`, активный чат, последний `extractHtmlBlocks`-блок) зовут `openPreview` — оба теперь чисто фронтовые, без Rust/событий.

**Ширина окна.** Эффект следит за `previewOpen` и зовёт Rust-команду ширины: закрыто → `BASE_WIDTH`, открыто → `BASE_WIDTH + PREVIEW_DELTA` (где `PREVIEW_DELTA` = ширина панели + gap). Значения-заглушки: `BASE_WIDTH = 760` (как сейчас), панель ≈ 380, gap ≈ 12 → открытая ширина ≈ 1152. Финальные числа правятся позже.

**Rust-команда ширины.** Команда `set_window_height` **заменяется** на **`set_window_width(width: f64)`** (высота окна теперь статична, динамический height-твин не нужен и удаляется вместе с ipc-обёрткой `setWindowHeight`). Новая команда переиспользует тот же ease-out-твин на фоновом потоке с диспетчем кадров через `run_on_main_thread` и guard-генератором `resize_gen`, но меняет **ширину**, сохраняя высоту. Якорь — левый-верхний угол (рост вправо). Кламп: если `x + новая_ширина` (физ. px) > правого края текущего монитора — сдвинуть `x` влево ровно настолько, чтобы окно влезло (через `set_position`). Чистую математику клампа (`x`, ширина, правый край монитора → новый `x`) вынести в маленький юнит-тестируемый helper (новый модуль `src-tauri/src/window_geom.rs`); прежний `preview.rs` (позиционирование окна превью) удаляется.

## Обработка ошибок

- `set_window_width` — `fire-and-forget` (как нынешний `set_window_height`): ошибки не критичны, окно остаётся в прежней ширине. Вне Tauri — ipc no-op.
- Пустой `previewHtml` при открытой панели — заглушка «Нет содержимого» (как раньше в окне).

## Тестирование

- **vitest** (правки существующих): `AnswerPanel` больше не принимает `expanded/onToggle` — обновить типы/использование; `usePreviewHtml.test.ts` удаляется. `extractHtmlBlocks`-тесты не трогаем.
- **cargo:** тесты `preview.rs` удаляются вместе с модулем; новый `window_geom.rs` покрыть юнит-тестами клампа ширины (рост вправо без упора; сдвиг влево при упоре в правый край монитора; отрицательный origin монитора).
- **Ручная приёмка:** чат сверху, композер снизу, без шеврона; высота окна — новая по умолчанию; клик по чипу/автооткрытие расширяет окно вправо, левый контент не двигается; ✕ сужает; у правого края экрана окно сдвигается влево; копирование кода; `auto_preview_html=false` гасит автооткрытие; перезапуск — высота консистентна.

## Вне рамок (YAGNI)

- Отдельные окна, пресеты раскладки, общие хоткеи на все окна (прежняя идея — отменена).
- Сохранение состояния панели превью между запусками; запоминание ширины панели в настройках.
- Тоггл JS, ограничения сети внутри iframe.
- Множественные панели/вкладки превью.

## Критерий готовности

- HUD: «Чат» сверху (переименован), композер снизу, сворачивания нет, чат всегда виден; высота окна — новая фиксированная.
- Превью открывается встроенной панелью справа (клик по чипу и автооткрытие под `auto_preview_html`), окно расширяется вправо без сдвига левого контента; ✕ закрывает и сужает; у края экрана срабатывает кламп влево; JS в sandbox-iframe живой.
- Отдельного окна превью и всей его инфраструктуры в коде нет (Rust/capability/роутинг/компонент/хук/событие/ipc удалены).
- `lint`/`typecheck`/`knip`/`format`/vitest/cargo/clippy — зелёные.
