# Фоновый аудио-буфер с транскрипцией по запросу

Дата: 2026-07-21
Статус: утверждён пользователем (архитектура A, дефолты скорректированы)

## Цель

Приложение непрерывно держит в памяти последние N секунд системного звука
(скользящее окно). По хоткею или кнопке содержимое окна транскрибируется в
текст и попадает в черновик чата — так же, как результат обычной PTT-записи.
Фича полностью отключаема тумблером в настройках.

## Требования (подтверждены пользователем)

- Буфер хранит **аудио** (кольцевой буфер), транскрипция — только по запросу.
- Источник — тот же, что у обычной записи: **системный звук** (Core Audio
  process tap).
- Забор буфера: **глобальный хоткей + кнопка в UI**; весь буфер
  транскрибируется, текст добавляется в черновик чата.
- Глубина хранения: настройка **4–10 секунд**, по умолчанию **4**.
- Тумблер включения/выключения; по умолчанию **включён**.
- Хоткей забора **изменяемый** в настройках; по умолчанию **F8**.

## Архитектура (вариант A — непрерывный consumer)

Существующий конвейер: RT-поток Core Audio (`io_proc`) → lock-free
транспортное кольцо (`ringbuf::HeapRb`, 8 с) → постоянный поток
`audio-consumer` (даунмикс в моно + инкрементальный ресемплинг rubato в
16 кГц) → аккумулятор сессии + `ChunkSink` стриминговой STT.

Надстройка:

- `io_proc` пропускает семплы при `recording || buffering` (сейчас — только
  `recording`).
- При включённом буфере `audio-consumer` не паркуется на condvar, а
  непрерывно дренирует транспортное кольцо через **долгоживущий ресемплер**.
  Каждый готовый 16 кГц-чанк идёт:
  - в скользящий буфер (`RollingBuffer`) — всегда;
  - в аккумулятор сессии и `ChunkSink` — только при активной PTT-сессии.
- При выключенном буфере поведение consumer байт-в-байт как сейчас
  (парковка на condvar, ресемплер на сессию, дренаж stale-данных на старте).
- «Последние N секунд» честные всегда, включая время PTT-записи.
- Забор = мгновенный снимок окна под мьютексом; далее классический путь
  транскрипции (`GroqStt::transcribe`), не стриминговый.

## Компоненты

### Rust

- **`audio.rs`** — новый тип `RollingBuffer`:
  - `VecDeque<f32>` с капом `secs × 16000` (16 кГц моно; 10 с ≈ 640 КБ);
  - методы `push_chunk(&[f32])`, `snapshot() -> Vec<f32>`,
    `set_capacity_secs(u64)` (с триммингом), `clear()`;
  - чистая логика без потоков, юнит-тесты в модуле.
- **`capture.rs`**:
  - `Shared` получает `buffering: AtomicBool` и
    `Arc<Mutex<RollingBuffer>>`;
  - `io_proc`: гейт `recording || buffering`;
  - `consumer_main`: непрерывный режим при `buffering`, долгоживущий
    ресемплер; на границе PTT-сессии допустима потеря хвоста ресемплера
    (~1–2 мс) — для речи незаметно;
  - публичные методы `SystemAudioCapture::set_buffering(bool)`,
    `buffer_snapshot() -> Vec<f32>`, `set_buffer_capacity_secs(u64)`.
- **`lib.rs`**:
  - команда `grab_buffer` и обработчик хоткея (через `defer()`):
    FSM == Idle → снимок → гейт тишины (RMS < 1e-3 → «Тишина») и
    минимальной длины (< 0.3 с → игнор) → FSM в Transcribing
    (`state-changed`) → снимок в `last_recording` (для Retry) →
    `GroqStt::transcribe` → `deliver_transcript` (клипборд +
    `transcript-ready`) → Idle;
  - FSM != Idle → `stt-error` «Сначала завершите текущую запись»;
  - `set_settings` diff-реакции: `buffer_enabled` (вкл/выкл буферизации,
    при выключении — `clear()`), `buffer_seconds` (смена капа с
    триммингом), `buffer_hotkey` (перерегистрация; регистрируется только
    при включённом буфере);
  - стартовый применитель в `setup_app`: если `buffer_enabled` и capture
    доступен — включить буферизацию и зарегистрировать хоткей;
  - пересоздание tap (смена устройства вывода): буфер начинается заново,
    потеря ≤10 с приемлема; буферизация переприменяется к новому instance.
- **`settings.rs`** — новые поля (со `#[serde(default)]`-миграцией):
  - `buffer_enabled: bool`, default `true`;
  - `buffer_seconds: u64`, clamp 4–10, default `4`;
  - `buffer_hotkey: String`, default `"F8"`;
  - именованные константы, clamp, тесты: `defaults_match_spec`,
    `load_missing_*_defaults`, clamp-тест.
- **`hotkey.rs`** — регистрация хоткея забора по образцу
  `register_teleprompter` (обработчик через `defer()`).

### Frontend (TS)

- **`ipc/types.ts`** — зеркальные поля `buffer_enabled`, `buffer_seconds`,
  `buffer_hotkey` в `Settings` и `DEFAULT_SETTINGS`.
- **`ipc/commands.ts`** — `grabBuffer()` (invoke `grab_buffer`,
  no-op в браузере).
- **`SettingsDialog.tsx`** — тумблер + числовое поле секунд (4–10, шаг 1)
  в STT-секции вкладки «Основное»; поле хоткея во вкладке «Хоткеи»
  (трим/фоллбек к дефолту при сохранении — как у остальных хоткеев).
- **`lib/hotkeys.ts`** — запись в `hotkeyGroups` для шпаргалки.
- **`StatusBar.tsx`** — иконка-кнопка (lucide `History`) рядом с EqBars:
  видна при `buffer_enabled`, активна только при состоянии `idle`,
  тултип «Расшифровать последние N с (хоткей)», вызывает `grabBuffer()`.

## Поток данных при заборе

1. F8 / кнопка → `grab_buffer`.
2. Снимок `RollingBuffer` (лок на миллисекунды, копия ≤160 тыс. f32).
3. Гейты: длина ≥ 0.3 с, RMS ≥ 1e-3.
4. `state-changed: transcribing` → EqBars анимируются primary-цветом.
5. Классическая транскрипция (WAV 16 кГц моно 16-bit, ≤ ~320 КБ).
6. `deliver_transcript`: клипборд + `transcript-ready` → фронт добавляет
   текст в черновик (+ `auto_send` при включённой настройке).
7. Ошибки → `stt-error`; ретраибельные — кнопка Retry
   (`retry_transcription` работает со снимком из `last_recording`).

## Ошибки и краевые случаи

- Нет TCC-гранта (capture = None): буферизация не стартует; grab даёт
  существующую ошибку «Нет разрешения…».
- Тишина/короткий буфер — гейты выше.
- Выключение тумблера: `set_buffering(false)` + немедленный `clear()`.
- Данные никогда не пишутся на диск; окно уже `contentProtected`.
- Сохранены инварианты: порядок остановки (`recording=false` → дренаж
  хвоста), порядок полей = порядок Drop в `SystemAudioCapture`, работа
  хоткеев только через `defer()`, никаких `MutexGuard` через `.await`,
  общий User-Agent у всех HTTP-клиентов.
