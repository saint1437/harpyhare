# Компактный UI: рейка табов слева, хоткеи размера окна, уплотнение

Дата: 2026-07-21. Статус: дизайн (реализация не начата).

## Задача

Три связанных изменения UI/UX:

1. **Хоткеи размера окна.** Cmd(+Ctrl)+Shift+стрелки меняют ширину (←/→) и высоту
   (↑/↓) окна с шагом `move_step`. Размер запоминается между запусками.
2. **Табы — вертикальная рейка слева.** Названия — просто цифры 1–6; переименование
   удаляется; закрытие — по ховеру (цифра сменяется на ×).
3. **Уплотнение.** Дефолт окна 960×680 (было 1140×860), поле промпта — 1 строка с
   аворостом (было ~4 фикс-минимум), шапка — одна строка, контролы Composer ниже и уже.

## Решения (утверждены пользователем)

- Хоткеи: **Cmd+Shift+стрелки** (жертвуем «выделить до края строки» в поле ввода —
  прецедент уже есть: Cmd+стрелки отданы движению окна).
- Табы: только цифры, × по ховеру, переименование под нож.
- Поле ввода: минимум 1–2 строки + авторост до потолка (~6 строк), дальше скролл.
- Дефолт окна: 960×680. Размер персистится в settings.json (+2 поля).

## Архитектура хоткей-ресайза: нативный монитор ловит, фронт управляет

Рассмотрены три варианта; выбран A.

- **A (выбран): монитор → событие → фронт → команда.** NSEvent-монитор поглощает
  Cmd/Ctrl+Shift+стрелку ДО WKWebView и эмитит `resize-key {dim, dir}`. Фронт владеет
  базовым размером, применяет шаг и клампы, зовёт `set_window_size`, персистит.
- B (отвергнут): всё в Rust. Rust не знает про открытое превью — персист ширины
  «база+превью» вместо базы, клампы грязные. Геометрия рвётся на два места.
- C (отвергнут): чистый JS keydown. Cmd+Shift+стрелки — выделение текста в textarea;
  полагаться на preventDefault в WKWebView — та же гонка, из-за которой Cmd+стрелки
  уже переведены на нативный монитор.

Почему источник истины — фронт: ширина чат-колонки фиксирована (инвариант твина
превью), композиция «база + панель превью» живёт во фронтовом `previewOpen`. Только
фронт знает, что значит текущая физическая ширина окна. Это повторяет существующие
паттерны: `toggle-teleprompter` (событие от хоткея → фронт решает), opacity
(bump на фронте + дебаунс-персист).

## Контракт Rust ⇄ фронт (изменения синхронны по обе стороны)

- **Событие** `resize-key` `{ dim: "width" | "height", dir: 1 | -1 }` — эмитит
  расширенный `install_move_keys_monitor` при Cmd/Ctrl+Shift+стрелке (без Shift —
  движение окна, как раньше). Добавляется в `EventMap` (`ipc/types.ts`).
- **Команда** `set_window_size(width, height)` **заменяет** `set_window_width(width)`
  (lib.rs `generate_handler!` + `ipc/commands.ts`). Тот же твин (ease-out,
  `resize_gen`, центрирование X через `centered_target_x`), высота интерполируется,
  верхний край Y фиксирован (рост вниз).
- **Settings 19 → 21 полей**: `window_width: f64` (дефолт 960), `window_height: f64`
  (дефолт 680). Клампы в `settings.rs`: ширина 880–1600, высота 520–1100
  (+ защита от не-finite, как у `chat_font_size`). Дефолты обязаны совпадать с
  `tauri.conf.json`.
- `tauri.conf.json`: окно 960×680.
- На старте (setup, после загрузки settings) Rust применяет персистнутый размер
  окна до показа.

## Фронтенд

### Геометрия

- Новый чистый модуль `lib/window-size.ts` (+ юнит-тесты): константы клампов
  (зеркало settings.rs), `stepWindowSize(size, dim, dir, step)` — шаг с клампом.
- `useWindowControls` расширяется: подписка на `resize-key` → шаг → кламп →
  `set_window_size(база + превью-экстра, высота)` → обновление `window_width/height`
  в настройках с дебаунс-персистом (паттерн `useBumpOpacity`). В браузерном моке —
  JS-фолбэк keydown на Cmd+Shift+стрелки (как для движения окна).
- `App.tsx`: `CHAT_COLUMN_WIDTH_PX` (константа) → деривация от
  `settings.window_width`: `chatColumnWidth = window_width − 2·SHELL_PADDING −
  RAIL_WIDTH − GAP`. Ширина окна при открытом превью:
  `window_width + PREVIEW_PANEL_WIDTH + GAP`. Инвариант «колонка чата фикс-ширины,
  панель клипается при твине» сохраняется — колонка меняется только дискретно,
  по нажатию хоткея.

### Рейка табов

- Новый компонент `TabRail` заменяет `ChatTabs` (файл переименовывается, старый
  удаляется). Вертикальная колонка слева на всю высоту шелла: квадраты ~28px,
  моно-цифра (индекс+1), активный — `bg-white/10 text-foreground`, неактивный —
  `text-muted-foreground hover:bg-white/5`. Ховер: цифра сменяется на × (клик —
  закрыть; × не показывается, когда чат один). Точка-пульс стрима — абсолютом в
  углу квадрата. Кнопка `+` — под табами (disabled при `CHAT_LIMIT`).
  Фон рейки — драг-зона окна (`useWindowDrag`).
- Переименование удаляется целиком: `renameChat` из `useChats`/`ChatsApi`,
  двойной клик, `RenameInput`. Поле `title` в модели чата и (де)сериализации
  остаётся — совместимость chats.json.
- `StatusBar` теряет слот `tabs` и становится одной строкой: кнопки окна · точка
  статуса · текст статуса (инлайн, truncate) · бейдж апдейта · шестерёнка.

### Уплотнение

- Composer: textarea `min-h-9` + авторост (`field-sizing-content` уже в ui/textarea)
  до `max-h-40`; контролы `h-7 text-[11px]`; селекты 96–128px по контенту;
  «Очистить»/«Контекст» → иконки-кнопки (Eraser / FileText) с `title`-тултипами,
  индикация непустого контекста — точка на иконке; «Стоп» показывается **вместо**
  «Отправить» во время стрима (сейчас обе кнопки рядом).
- Шелл: `p-4 → p-3`, `gap-3 → gap-2.5`. Радиус 22px не трогаем (связан с
  `DialogOverlay` — инвариант скруглённого бэкдропа).
- Текст чата не уменьшается — им управляет `chat_font_size`.
- `HotkeyHints`: добавляется `⌘⇧←→↑↓ размер`.

## Ошибки и краевые случаи

- Зажатая клавиша: NSEvent автоповтор → каждое нажатие — новый твин; `resize_gen`
  отменяет предыдущий, твин стартует от текущей ширины. Поведение уже отработано
  превью-твином.
- Ресайз при открытом превью: меняется база, окно = база + экстра. Кламп — по базе.
- Старый settings.json без новых полей: serde-дефолты 960×680 + кламп.
- Монитор без окна/вне Tauri: событие просто не эмитится; в браузере работает
  JS-фолбэк (без реального окна — no-op команд, как всё в `ipc/`).
