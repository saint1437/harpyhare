# Множественные чаты с памятью — дизайн

**Дата:** 2026-06-11
**Статус:** утверждён, готов к плану реализации

## Задача

Сейчас приложение полностью одноразовое: `llm::build_request_body` шлёт один
пользовательский вопрос без истории, а `useClaudeStream` хранит единственный
`answer`, который затирается при каждом новом вопросе. Понятия «чат», истории
сообщений и многоходового диалога нет ни на фронте, ни в Rust.

Нужно добавить **множественные чаты с памятью**:

- Внутри одного чата — полноценный многоходовой диалог: Claude помнит всю
  предыдущую переписку (история шлётся в Anthropic API).
- Новый чат начинает историю с нуля; чаты независимы.
- Между чатами можно переключаться; **стримы идут параллельно и независимо**
  (генерация в чате A продолжается, пока смотришь чат B).
- Чаты с перепиской **переживают перезапуск** приложения (персистентность на диск).

## Решения (зафиксированы в брейншторме)

| Вопрос | Решение |
|---|---|
| Что такое «чат» | Многоходовой диалог с памятью; история шлётся в API |
| Персистентность | Да, восстанавливать после перезапуска |
| Размещение управления | Вкладки в верхней строке (`StatusBar`), `＋` в конце ряда |
| Параллельные стримы | Да, независимые стримы на чат |

## Модель данных (фронт — источник истины)

```ts
type Role = "user" | "assistant";

interface ChatMessage {
  role: Role;
  text: string;
  images: ImagePayload[]; // только в user-сообщениях; в сериализации на диск стрипаются
}

interface Chat {
  id: string;            // uuid
  title: string;         // авто из первого вопроса, иначе "Чат N"
  messages: ChatMessage[];
  draft: string;            // незавершённый ввод — сохраняется при переключении
  draftAttachments: Attachment[];
}

// Состояние приложения:
//   chats: Chat[]
//   activeId: string
```

Новый хук `useChats` инкапсулирует список чатов, активный чат, операции
создания/удаления/переключения, сохранение драфта и персистентность.
`App.tsx` работает с активным чатом вместо локальных `text`/`answer`.

## Фронтенд

### `src/hooks/useChats.ts` (новый)
- Держит `chats`, `activeId`; селектор активного чата.
- `newChat()` — создаёт чат, переключает на него, фокус в композер. Лимит **6**
  чатов (при достижении `＋` неактивна).
- `removeChat(id)` — удаление; последний чат удалить нельзя (всегда ≥1); удаление
  активного → переключение на соседний.
- `selectChat(id)` — переключение; драфт текущего чата сохраняется.
- `appendUserMessage(id, text, images)` / `appendAssistantMessage(id, text)` —
  дописывание истории.
- `setDraft(id, text, attachments)`.
- Дебаунс-сохранение на диск при изменениях (см. «Персистентность»).
- Юнит-тесты: создание/удаление/переключение, сохранение драфта, лимит 6,
  запрет удаления последнего.

### `src/hooks/useClaudeStream.ts` (правка → по-чатный)
- Стрим становится **по-чатным**: буфер и флаг `streaming` на каждый `chatId`;
  дельты роутятся по `chatId` из события.
- Глобальный запрет «не слать поверх активного стрима» убирается; запрет
  становится per-chat: нельзя слать в чат, где уже идёт генерация; в другом —
  можно.
- Сохраняем существующие инварианты: rAF-флаш батчингом, отмена pending rAF на
  unmount, гейт запоздалых дельт после `stop`/`done` (теперь по `chatId`).
- На `llm-done` для чата его текущий буфер дописывается в `messages` как
  assistant-turn.
- Юнит-тесты: роутинг дельт по `chatId`, два параллельных стрима не смешиваются.

### Компоненты
- `StatusBar.tsx` — добавляется ряд вкладок `[1][2][3][＋]` слева от шестерёнки.
  Активная вкладка подсвечена; на вкладке со стримом — индикатор (точка/спиннер);
  наведение → крестик `×` для удаления; тултип = начало первого вопроса или
  «Чат N».
- `AnswerPanel.tsx` → **лента диалога**: чередование сообщений «ты» / Claude,
  markdown в ответах Claude. Сохраняется поведение свёрнуто/развёрнуто: пустой
  новый чат → компактное окно (`COMPACT_HEIGHT`); авто-раскрытие на первой дельте
  активного чата.
- `Composer.tsx` — без структурных изменений; пишет в `draft` активного чата.
- Возможен новый небольшой компонент `ChatTabs.tsx` для ряда вкладок (вынести из
  `StatusBar`, если разрастётся).

### Поведение
- PTT-запись и вставка картинок работают в активном чате, как сейчас
  (транскрипт уходит в `draft`/отправку активного чата).
- Окно: высота по-прежнему `state-driven` (`COMPACT_HEIGHT` ↔ `FULL_HEIGHT`),
  завязана на наличие контента/раскрытие активного чата.

## Бэкенд (Rust) — умеренная правка

### `llm.rs`
- `build_request_body(model, system, &messages)` собирает массив `messages` для
  Anthropic: user-сообщения с image-блоками, assistant-сообщения текстом —
  вместо одного user-сообщения. Адаптивный thinking и остальная логика тела
  запроса не меняются.
- Новый тип `ChatMessage { role: String /* "user"|"assistant" */, text: String,
  images: Vec<ImageAttachment> }` (или эквивалент), сериализуемый из фронта.
- Обновляются юнит-тесты `build_request_body` (теперь несколько сообщений,
  чередование ролей, картинки в user-сообщении).

### `lib.rs`
- `send_to_claude(app, messages: Vec<ChatMessage>, chat_id: String)` — добавляется
  `chat_id`.
- События несут id чата:
  - `llm-delta` → `{ chatId, delta }`
  - `llm-done` → `{ chatId }`
  - `llm-error` → `{ chatId, message }`
- Отмена становится по-чатной: вместо `Mutex<Option<CancellationToken>>` —
  `Mutex<HashMap<String, CancellationToken>>`. При `send` для `chat_id` кладём
  токен (отменяя/заменяя прежний для того же чата); по `done`/`error` токен чата
  удаляется.
- `cancel_stream(app, chat_id: String)` — отменяет конкретный чат.
- Параллельность: команды Tauri выполняются на async-runtime, несколько
  `send_to_claude` крутятся параллельно; общего изменяемого состояния, кроме
  мапы токенов, нет (клиент клонируется до await, как сейчас).

### Контракт IPC (держать 1:1)
- `src/ipc/types.ts` — `EventMap` обновляется: `llm-delta`/`llm-done`/`llm-error`
  получают `chatId`.
- `src/ipc/commands.ts` — `sendToClaude(messages, chatId)`,
  `cancelStream(chatId)`.
- `src/ipc/events.ts` — типы слушателей под новые payload.
- Все команды/события продолжают no-op в браузере (browser-mock).

## Персистентность — Rust-файл `chats.json`

- Файл `~/Library/Application Support/com.itech.voice/chats.json`, рядом с
  `settings.json`. Атомарная запись с правами `0600`, по образцу `settings.rs`.
- Rust хранит **непрозрачную строку** (JSON-схему владеет фронт — не дублируем
  модель сообщений в Rust). Команды:
  - `load_chats() -> String` (пустая строка / отсутствие файла → фронт стартует с
    одним пустым чатом).
  - `save_chats(json: String)` — атомарная запись.
- Фронт сохраняет с **дебаунсом** при изменениях `chats`/`activeId`.
- **Картинки не сохраняются**: при сериализации `images` стрипаются (текст и
  ответы остаются). После перезапуска восстановленная история — текстовая;
  дозапросы в восстановленном чате шлют текстовую историю. Юнит-тест на стрип.
- *Отклонённая альтернатива:* `localStorage` (ноль Rust), но ломает конвенцию
  «Rust владеет хранением + атомарный 0600» и хуже инспектируется.

## Тестирование

- `useChats` — юнит-тесты (создание/удаление/переключение, драфт, лимит 6,
  запрет удаления последнего).
- `useClaudeStream` — роутинг дельт по `chatId`, изоляция двух параллельных
  стримов.
- `build_request_body` (Rust) — несколько сообщений, чередование ролей, картинки.
- Сериализация для персистентности (стрип картинок) — юнит-тест в `src/lib/`.
