# Дизайн: захват системного звука → расшифровка → ответ Claude

Дата: 2026-06-10
Статус: утверждён пользователем (детали — в этом документе)

## Цель

Desktop-приложение для macOS: пользователь зажимает глобальный хоткей — записывается системный звук (например, голос из видео в другом приложении); отпускает — запись распознаётся в текст (русская речь), текст попадает в буфер обмена и в редактируемое поле приложения; оттуда одним действием отправляется в Claude (Anthropic API), ответ стримится в окно приложения.

## Требования (зафиксированы с пользователем)

- Платформа: **только macOS** (машина разработки/использования: MacBook Air M5, 16 ГБ, macOS 26 / Darwin 25).
- Язык речи: **только русский**.
- Режим: **push-to-talk** — запись пока зажат хоткей, распознавание после отпускания. Стриминговое распознавание не требуется.
- Источник: **только системный звук** (микрофон не нужен).
- Результат распознавания: в **буфер обмена** + в **редактируемый textarea** приложения.
- Отправка текста в **Anthropic API (Claude)**, ответ отображается в приложении (стримингом).
- STT: **только облако, без локальных моделей** (требование пользователя). Провайдер: **Groq** (`whisper-large-v3-turbo`).
- Приоритеты: очень высокая скорость, нормальная точность.
- К сообщению можно прикладывать **скриншоты из буфера обмена** (Cmd+V) — уходят в Claude вместе с текстом (vision).
- **Прозрачность окна** настраивается; окно можно **двигать с клавиатуры** (Cmd+стрелки) на настраиваемый шаг.
- Качество кода: чистый, минимальный (без спекулятивных абстракций и фич «на будущее»), вся новая логика покрывается юнит-тестами.

| Слой | Выбор |

## Архитектура и компоненты (Rust)

### 1. `capture` — захват системного звука
- Core Audio process tap на весь системный вывод (`CATapDescription` / `AudioHardwareCreateProcessTap` через `cidre`). Tap и aggregate device создаются при старте приложения (чтобы не платить задержку на каждом нажатии); IO-callback запускается/останавливается по хоткею.
- Формат от системы: f32, 48 кГц, стерео. Конвейер: даунмикс в моно (среднее каналов) → ресемплинг до 16 кГц → накопление `Vec<f32>` в памяти.
- Лимиты: максимум **10 минут** записи (автостоп + сразу распознавание); минимум **0.3 сек** (короче — игнорировать).
- Память: 16 кГц × 4 байта × 600 сек ≈ 38 МБ максимум — приемлемо.

### 2. `stt` — распознавание (облако, Groq)
- Трейт `SttEngine { async fn transcribe(&self, samples_16k_mono: &[f32]) -> Result<String> }` — чтобы провайдера можно было заменить одной реализацией.
- Реализация `GroqStt`:
  - Буфер → WAV (16 кГц, моно, 16-bit PCM; минутная запись ≈ 2 МБ).
  - `POST https://api.groq.com/openai/v1/audio/transcriptions`, `multipart/form-data`: `file` (audio.wav), `model=whisper-large-v3-turbo`, `language=ru`, `temperature=0`, `response_format=json`.
  - Заголовок `Authorization: Bearer <GROQ_API_KEY>`. Таймаут 60 сек.
- **Гейт тишины**: перед отправкой считается RMS буфера; если ниже порога (стартовое значение 1e-3, подбирается при тестировании) — запрос не отправляется, пользователю показывается «Тишина — нечего распознавать». Это же отсекает известные галлюцинации Whisper на тишине.
- Аудио-буфер последней записи хранится до успешного распознавания или очистки — кнопка «Повторить» переотправляет без новой записи.

### 3. `hotkey` — push-to-talk
- `tauri-plugin-global-shortcut`: `ShortcutState::Pressed` → старт записи, `Released` → стоп. Работает при любом активном приложении, прав Accessibility **не требует**.
- Дефолтный хоткей: **V** (без модификаторов, настраивается).
  - **Известный эффект**: глобальный хоткей на голую букву перехватывает её во всей системе — пока приложение запущено, символ «v»/«м» не печатается ни в одном приложении. Это осознанный выбор под сценарий «слушаю видео»; хоткей меняется в настройках.
  - **Смягчение**: пока фокус находится в текстовых полях самого приложения (textarea, настройки), push-to-talk-хоткей временно снимается с регистрации и возвращается при потере фокуса — внутри приложения печатать можно всегда.
- **Esc** отменяет текущую запись (буфер сбрасывается). Esc регистрируется как глобальный шорткат **только на время записи** и снимается сразу после — иначе приложение перехватывало бы Esc во всей системе.

### 4. `llm` — клиент Anthropic
- Официального Rust SDK нет → raw HTTP (санкционированный путь для Rust).
- `POST https://api.anthropic.com/v1/messages`, заголовки: `x-api-key: <ключ>`, `anthropic-version: 2023-06-01`, `content-type: application/json`.
- Тело запроса:
  ```json
  {
    "model": "claude-opus-4-8",
    "max_tokens": 64000,
    "stream": true,
    "thinking": {"type": "adaptive"},
    "system": "<системный промпт из настроек>",
    "messages": [{"role": "user", "content": [
      {"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": "<скриншот, если приложен>"}},
      {"type": "text", "text": "<текст из textarea>"}
    ]}]
  }
  ```
- Если вложений нет, `content` — просто строка. Сборка `content`-блоков — отдельная чистая функция (покрывается юнит-тестами). Image-блоки идут перед текстом (рекомендация Anthropic для vision).
- Модель по умолчанию `claude-opus-4-8`; в настройках выбор: `claude-opus-4-8`, `claude-sonnet-4-6`, `claude-haiku-4-5`. Для `claude-haiku-4-5` поле `thinking` не отправляется.
- Дефолтный системный промпт: «Ты получаешь расшифровку русской речи из аудио (могут быть ошибки распознавания). Ответь на вопрос или прокомментируй сказанное кратко и по делу, на русском.»
- SSE-парсер: накапливаем `content_block_delta` → `text_delta` и шлём в UI событиями; `thinking`-дельты игнорируем (на opus-4-8 их текст по умолчанию пуст); `message_delta` даёт `stop_reason`; `error`-события и обрыв соединения → ошибка в UI с сохранением частичного ответа.
- Один обмен «вопрос → ответ», без истории диалога (v1). Кнопка «Стоп» абортирует текущий запрос (drop future / abort handle).

### 5. `clipboard`, `settings`
- После успешного распознавания текст пишется в системный буфер обмена и отправляется в UI.
- Настройки (`settings.json`, права 600):
  - `anthropic_api_key`, `groq_api_key`
  - `model` (по умолчанию `claude-opus-4-8`)
  - `system_prompt`
  - `hotkey` (по умолчанию `V`)
  - `auto_send` (bool, по умолчанию `false`)
  - `window_opacity` (0.2–1.0, по умолчанию 1.0; значения вне диапазона клампятся)
  - `move_step` (целое, px за одно нажатие Cmd+стрелки, 1–200, по умолчанию 20)

### 6. Окно: прозрачность и перемещение с клавиатуры
- Главное окно создаётся с `transparent: true` (на macOS требует `app.macOSPrivateApi: true` в `tauri.conf.json`); прозрачность применяется через CSS-переменную на корневом контейнере из настройки `window_opacity` — слайдер в настройках действует мгновенно, без перезапуска.
- **Cmd+← / → / ↑ / ↓** двигает окно на `move_step` px по соответствующей оси. Реализация: keydown-обработчик в webview → Tauri-команда `move_window_by(dx, dy)` (сдвиг outer-позиции окна). Работает, когда окно приложения в фокусе. Примечание: внутри textarea это перекрывает стандартную навигацию Cmd+←/→ (начало/конец строки); навигация по словам Option+стрелки сохраняется.

### 7. Вложения-скриншоты
- **Cmd+V** при изображении в буфере обмена (стандартное событие `paste` в webview отдаёт image-блоб — плагины не нужны) → изображение прикладывается к будущему сообщению; текстовая вставка работает как обычно.
- Превью-чипы вложений под textarea, у каждого крестик удаления. Лимит: **до 5 изображений**.
- Изображение больше лимита API (5 МБ) даунскейлится на canvas до попадания в лимит (PNG → при необходимости JPEG q0.85).
- Новая расшифровка заменяет только текст — вложения не трогает. «Очистить» убирает и текст, и вложения. После отправки composer не очищается автоматически (поведение единообразно с текстом).

## Поток данных и состояния

```
V зажата ──▶ Recording (оверлей «● Запись» виден)
V отпущена ─▶ Transcribing ─▶ WAV ─▶ Groq ─▶ текст
        ├──▶ системный буфер обмена
        └──▶ textarea в окне (редактируемый)
«Отправить» / Cmd+Enter / авто-отправка
        ─▶ Anthropic SSE ─▶ дельты в область ответа ─▶ готово
```

- Машина состояний записи: `Idle → Recording → Transcribing → Idle`. Нажатие хоткея в состоянии `Transcribing` игнорируется (индикатор занятости).
- Стриминг ответа Claude — независимый от записи процесс: можно записывать следующий вопрос во время генерации ответа. Новая расшифровка **заменяет** содержимое textarea.

### Tauri-интерфейс (Rust ⇄ WebView)

- Команды (invoke): `send_to_claude(text, images: Vec<ImageAttachment>)`, `cancel_stream()`, `retry_transcription()`, `get_settings()`, `set_settings(s)`, `open_audio_permission_settings()`, `move_window_by(dx, dy)`, `set_ptt_suspended(bool)` (снятие/возврат push-to-talk-хоткея при фокусе в текстовых полях).
- События (emit): `state-changed(Idle|Recording|Transcribing)`, `transcript-ready(text)`, `stt-error(message)`, `llm-delta(text)`, `llm-done`, `llm-error(message)`.

## UI

- **Стиль**: современный и минималистичный — тёмная палитра, системная типографика, без визуального шума; ничего лишнего сверх описанного ниже. При реализации UI используется skill `frontend-design`.
- **Главное окно**: строка состояния; composer — textarea с расшифровкой + ряд превью-чипов вложений (скриншоты из Cmd+V, крестик удаления); кнопки «Отправить» (дубль Cmd+Enter), «Стоп» (виден во время стрима), «Очистить»; область ответа Claude (markdown через `marked` + санитайзинг), кнопка «Копировать ответ»; иконка-шестерёнка → настройки.
- **Настройки** (модалка): два API-ключа (поля password), селект модели, textarea системного промпта, поле хоткея, тумблер авто-отправки, слайдер прозрачности окна (20–100%), числовое поле шага перемещения окна (px).
- **Оверлей записи**: отдельное Tauri-окно ~140×36, верхний правый угол экрана, `always_on_top`, без декораций, не принимает фокус, видно на всех рабочих столах; показывается только в состоянии `Recording`.

## Разрешения macOS

- Единственное требуемое: **«Запись системного звука»** (NSAudioCaptureUsageDescription в Info.plist; системный диалог при первом создании tap; панель: Конфиденциальность и безопасность → Запись экрана и системного звука → «Только запись системного звука»).
- Не требуются: микрофон, Accessibility, запись экрана, Input Monitoring.
- Если права нет (создание tap возвращает ошибку): в UI постоянный баннер с объяснением и кнопкой `open_audio_permission_settings()` (открывает `x-apple.systempreferences:com.apple.preference.security?Privacy_AudioCapture`).

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет права записи системного звука | Баннер + кнопка в Системные настройки; хоткей в это время показывает тот же баннер |
| Нажатие хоткея < 0.3 сек | Игнор без сообщений |
| RMS ниже порога тишины | «Тишина — нечего распознавать», запрос не отправляется |
| Groq 401 | «Неверный ключ Groq — проверь в настройках» |
| Groq 429 / 5xx | «Сервис перегружен, попробуй позже» + «Повторить» (буфер сохранён) |
| Groq сеть/таймаут | «Нет соединения — проверь интернет/VPN» + «Повторить» |
| Anthropic 401 | «Неверный ключ Anthropic — проверь в настройках» |
| Anthropic 429 / 529 / 5xx / сеть | Сообщение + «Повторить»; частичный ответ остаётся в окне |
| Обрыв SSE посреди ответа | Частичный ответ остаётся, статус «обрыв соединения», «Повторить» переотправляет вопрос целиком |
| Запись достигла 10 мин | Автостоп + переход к распознаванию + уведомление в строке состояния |

## Тестирование

Правило: **вся новая логика покрывается юнит-тестами**; в коде нет ничего сверх требований спеки (YAGNI). Реализация ведётся через TDD.

- **Юнит, Rust (cargo test)**: даунмикс+ресемплинг на синтетической синусоиде (частота сохраняется, длина корректна); WAV-заголовок/длина; RMS-гейт тишины (тихий и громкий буферы); SSE-парсер на текстовых фикстурах реальных событий Anthropic (message_start → дельты → message_stop, а также error-событие); сборка `content`-блоков (только текст / текст+изображения, порядок блоков); (де)сериализация настроек, клампинг `window_opacity` и `move_step`; вычисление сдвига окна по (клавиша, шаг).
- **Юнит, TS (vitest)**: чистые функции composer'а — извлечение изображений из paste-события (по mime), решение о даунскейле (размер→да/нет/целевой масштаб), ограничение «до 5 вложений», построение payload для `send_to_claude`.
- **Интеграционные (wiremock)**: `GroqStt` против мок-сервера (успех, 401, 429, таймаут); Anthropic-клиент против мок-SSE (полный стрим, обрыв посередине).
- **Ручной чеклист** (WKWebView недоступен для браузерной автоматизации): первый запуск → диалог права → выдача; видео на YouTube в Safari, приложение не в фокусе → V зажата/отпущена → текст в буфере и в поле ≤ 1.5 сек; печать «v»/«м» в textarea приложения работает (хоткей снят при фокусе), в чужом приложении — перехватывается (ожидаемо); правка текста → Cmd+Enter → стрим ответа; вставка скриншота Cmd+V → чип → отправка с картинкой; «Стоп» посреди стрима; Esc во время записи; слайдер прозрачности действует сразу; Cmd+стрелки двигают окно на настроенный шаг; поведение с выключенным VPN (понятные ошибки); смена хоткея в настройках.

## Производительность (цели)

- Отпускание кнопки → текст в поле: **0.5–1.5 сек** (WAV-кодирование <50 мс, остальное — сеть + Groq).
- Отправка → первый токен Claude: ~1–2 сек (сеть).
- Старт записи после нажатия: <50 мс (tap уже создан).

## Риски и запасные пути

1. **`cidre` process tap** — самая рискованная часть (малодокументированный API). План: первая задача реализации — изолированный спайк «записать 5 сек системного звука в WAV». Если cidre упирается — запасной путь: Swift-шим (~200 строк, `swiftc` на этапе сборки), пишущий PCM в stdout, Rust читает из дочернего процесса. Интерфейс `capture`-модуля от этого не меняется.
2. **Groq из РФ** — нужен VPN; для пользователя это уже данность (Anthropic API тоже требует VPN). Ошибки сети формулируются с упоминанием VPN.
3. **Галлюцинации Whisper на тишине/музыке** — RMS-гейт + `temperature=0`; если останутся артефакты на музыке без речи, это приемлемо (текст редактируемый).
4. **Хоткей V перехватывает букву во всех приложениях** — осознанный компромисс (см. раздел hotkey): авто-снятие при фокусе в полях самого приложения + настройка другой клавиши.

## Вне скоупа v1

- Микрофон и микширование источников.
- История диалога с Claude (multi-turn) — структура `messages` позволяет добавить позже.
- Стриминговое распознавание (живые субтитры).
- Авто-вставка текста в другие приложения (Accessibility).
- Хранение ключей в Keychain.
- Подпись/нотаризация и распространение; Windows/Linux.
