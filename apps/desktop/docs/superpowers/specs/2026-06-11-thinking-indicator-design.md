# Индикатор «Думает…» при ожидании ответа Claude — дизайн

**Дата:** 2026-06-11
**Статус:** утверждён, готов к плану реализации

## Задача

Когда отправлен запрос к Claude, но текст ответа ещё не пошёл, в приложении нет видимого индикатора — экран выглядит «мёртвым». Для больших задач это особенно заметно: для opus/sonnet включён `adaptive thinking`, а `thinking_delta` не форвардятся на фронт (`llm.rs` шлёт только `text_delta`), поэтому фаза размышления модели может длиться долго при полном отсутствии дельт. Показать в ленте анимированный статус **«Думает… {N}с»** на эту фазу ожидания; как только пошёл текст — статус исчезает, и дальше «индикатором» служит сам стримящийся ответ (как в Claude).

## Решения (зафиксированы в брейншторме)

| Вопрос | Решение |
|---|---|
| Что показывать | «Думает… {N}с» (анимированные точки + счётчик секунд) до первого токена; затем — стримящийся текст без отдельного лейбла (как Claude) |
| Где | В ленте чата (`AnswerPanel`), на месте будущего ответа. `StatusBar` не трогаем |
| Источник фазы | Фронт-онли: фаза ожидания = `streaming && !partial` (включает реальный thinking). Форвардинг thinking-контента из Rust — НЕ делаем |
| Таймер | Счётчик секунд, тик раз в 1с, на фазе ожидания |
| Точность таймера при переключении в фоновый «думающий» чат | Отсчёт от момента маунта индикатора (≈ переключение), не от реальной отправки — лёгкий недосчёт, принимаем (YAGNI) |

## Текущее состояние (для контекста)

- `useClaudeStream`: `send()` сразу ставит `streaming[chatId]=true` и `partial[chatId]=""`; `llm-delta` копит `partial`; `llm-done`/`llm-error` гасят `streaming`. `App` передаёт в `AnswerPanel` `partial = activeStreaming ? (stream.partial[activeId] ?? "") : null` и `streaming = activeStreaming`.
- `AnswerPanel`: рендерит сообщения, затем `{partial !== null && partial !== "" && <Assistant text={partial} .../>}`. Пустая лента — «Чат появится здесь». Проп `streaming` уже есть (используется в `canCopy`).
- `StatusBar`: отражает только `RecorderState` (idle/recording/transcribing) — про стрим Claude ничего. Кнопка «Стоп» в `Composer` показывается при `streaming`.
- `llm.rs`: `SseParser` форвардит только `text_delta`; `thinking_delta` игнорируется (комментарий «thinking-дельты игнорируются»). `adaptive thinking` включён для не-haiku.

## Поведение

- Пока `streaming === true` для активного чата и текста ещё нет (`partial` пустой) — в ленте, на месте будущего ответа ассистента, показывается **`ThinkingIndicator`**: анимированные точки + «Думает… {N}с», где N — секунды с момента появления индикатора, тикает раз в секунду.
- Как только приходит первый текстовый токен (`partial` непустой) — индикатор исчезает, рендерится стримящийся `Assistant text={partial}` (как сейчас). Отдельного лейбла на фазе текста нет.
- Стрим завершился/отменён/ошибка без текста: `streaming` гаснет → индикатор исчезает; ошибка идёт в существующую строку ошибок (без изменений).
- Кнопка «Стоп» в композере доступна всю фазу (без изменений).

## Архитектура

- **`src/components/ThinkingIndicator.tsx`** (новый, презентационный):
  - Внутренний таймер: `useState<number>(0)` + `useEffect(() => { const id = setInterval(() => setSeconds(s => s+1), 1000); return () => clearInterval(id); }, [])`. Старт отсчёта — момент маунта.
  - Рендер в стиле строки ассистента: анимированные точки (CSS/`animate-pulse` или тройка точек) + текст «Думает… {seconds}с».
  - Без пропсов: текст «Думает» фиксирован, секунды берёт из внутреннего таймера.
- **`AnswerPanel.tsx`**: в скролл-зоне, после списка сообщений и рядом с текущим рендером `partial`, добавить:
  `{streaming && (partial === null || partial === "") && <ThinkingIndicator />}`.
  Скролл-эффект (`scrollTop = scrollHeight`) уже зависит от `[messages, partial]`; появление индикатора по `streaming` — единичное изменение высоты, автоскролл не критичен (можно оставить как есть).

Чистый фронт: без Rust, без новых IPC/событий, без изменения `llm.rs`.

## Поток данных

1. Отправка → `useClaudeStream.send` → `streaming[chatId]=true`, `partial[chatId]=""`.
2. `App` → `AnswerPanel` (`streaming=true`, `partial=""`) → рендерит `ThinkingIndicator` (таймер тикает).
3. Первый `llm-delta` → `partial` непустой → условие индикатора ложно → исчезает, рендерится стримящийся текст.
4. `llm-done`/`llm-error`/`stop` → `streaming=false` → ни индикатора, ни (для ошибки) текста; ошибка — в строке ошибок.

## Тестирование

- **vitest** `src/components/ThinkingIndicator.test.tsx` (fake timers): на маунте показывает «Думает… 0с»; после `vi.advanceTimersByTime(2000)` — «Думает… 2с». (Текст «Думает…» присутствует, число растёт.)
- **vitest** (опционально, по месту) `AnswerPanel`: при `streaming && partial===""` индикатор в DOM; при `partial="текст"` индикатора нет, есть текст. Если рендер-тест на `AnswerPanel` окажется хрупким — ограничиться тестом `ThinkingIndicator` + ручной приёмкой (компоненты в репо в основном без тестов).
- **Ручная приёмка:** отправить «напиши тетрис одним HTML-файлом» → сразу видно «Думает… Nс», счётчик растёт; как пошёл текст — индикатор сменился ответом; «Стоп» работает; ошибка/отмена убирает индикатор.

## Вне рамок (YAGNI)

- Форвардинг thinking-контента/сигнала фазы из Rust (`llm.rs`).
- Индикатор/состояние стрима в `StatusBar`.
- Мигающий курсор у стримящегося текста, лейбл «Печатает…» на фазе текста.
- Точный отсчёт таймера от реальной отправки при переключении в фоновый чат.
- Таймаут/автоотмена «зависшего» стрима.

## Критерий готовности

- На фазе ожидания (стрим идёт, текста нет) в ленте виден анимированный «Думает… {N}с» с растущим счётчиком; на тетрисе сразу понятно, что процесс идёт.
- При первом токене индикатор сменяется стримящимся ответом; при завершении/ошибке/отмене — исчезает.
- Без правок Rust/IPC; `lint`/`typecheck`/`knip`/`format`/vitest/cargo — зелёные.
