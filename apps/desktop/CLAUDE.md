# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**harpyhare** — a macOS-only Tauri 2 desktop app (процесс маскируется под «Audio System», бренд `harpyhare` — только в UI). Hold a push-to-talk key → capture **system audio** (e.g. voice from a video) → transcribe via Groq Whisper → edit the text (with pasted screenshots) → stream an answer from the Anthropic API. A single floating, frameless, always-on-top HUD window.

Two halves: a **Rust backend** (`src-tauri/src/`) and a **React 19 frontend** (`src/`). The backend does all the privileged/native work; the frontend is pure UI over a typed IPC boundary.

Живёт в `apps/desktop/` монорепозитория **harpyhare** (Nx + npm workspaces; лендинг — `apps/landing`). Все пути и команды ниже — относительно `apps/desktop/` (запускать из этой папки, либо через Nx из корня: `nx <target> desktop`). Обзор монорепо — в корневом `CLAUDE.md`.

## Code style

- **Комментарии в коде запрещены полностью.** Знание живёт в говорящих именах; неочевидные инварианты и «почему» — в этом файле, а не в комментариях.
- **Хардкод запрещён.** Магические значения → именованные константы; вычислимое — деривация, а не копия; поведение моделей — по capabilities API, а не по спискам имён (единственные допустимые исключения по имени описаны в разделе про модели).
- **Одна ответственность.** Функции/компоненты, делающие несколько вещей, дробятся на маленькие с говорящими именами.
- **Публичные контракты меняются только синхронно по обе стороны.** IPC-команды/события, serde-ключи, форматы на диске (settings.json, chats.json), строковый формат хоткеев (`hotkeyFromEvent` ⇄ `parse_hotkey`).

## The Rust ⇄ frontend contract (read this first)

The backend exposes a **fixed set of commands and events**; the frontend mirrors them 1:1. When changing one side, change the other and keep names identical.

- **Commands** are registered in `generate_handler!` in `src-tauri/src/lib.rs`; argument names map snake_case (Rust) → camelCase (JS invoke). The frontend wrappers are in `src/ipc/commands.ts`.
- **Events** are `app.emit("name", payload)` in `lib.rs`; the frontend listens via `src/ipc/events.ts`, typed by `EventMap` in `src/ipc/types.ts` (`state-changed`, `transcript-ready`, `stt-error`, `llm-delta`, `llm-done`, `llm-error`, `update-available`, `update-progress`, `update-done`, `toggle-teleprompter`, `resize-key`, `llm-usage`). LLM-события несут `chatId` (`{ chatId, delta }` / `{ chatId }` / `{ chatId, message }`) — стримы независимы по чатам. `llm-delta` коалесируются на стороне Rust (флашер ~25мс в `send_to_claude`); финальный дрен буфера обязан уйти **до** `llm-done`, иначе фронт потеряет хвост ответа. **Заполненность контекста** — целиком из API, без хардкода окон: числитель — `llm-usage {chatId, inputTokens}` из `message_start.usage` стрима (СУММА `input_tokens + cache_read_input_tokens + cache_creation_input_tokens` — при включённом prompt-cache голый `input_tokens` почти нулевой!), знаменатель — `ModelInfo.maxInputTokens`; фронт: событие пишется в `Chat.lastInputTokens` (персистится в chats.json — мгновенный фолбэк при входе в чат). **Основной показатель — проекция через `count_tokens`**: команда `count_chat_tokens` (Rust `AnthropicClient::count_tokens`, `POST /v1/messages/count_tokens`, бесплатный, без лиза на прокси) считает, сколько займёт СЛЕДУЮЩИЙ запрос (system + текущая история), хук `useProjectedContextTokens` в App.tsx (дебаунс 400мс, для пустого чата — плейсхолдер-сообщение `.`, чтобы учесть вес библиотечных материалов ещё до отправки). Итоговый `usedTokens = projected || lastInputTokens` → `ContextUsageGauge` в шапке (StatusBar, перед иконками действий; скрыт, пока данных нет или окно модели неизвестно). **Прокси (репо `itech-relay`) обязан маршрутизировать `/v1/messages/count_tokens`** — иначе 404 и проекция не работает.
- `Settings` (28 fields) is defined identically in `src-tauri/src/settings.rs` and `src/ipc/types.ts`. Глобального системного промпта и модели в Settings нет — вместо них `prompt_presets: {id,name,text}[]` (сид «Расшифровка речи», id `transcription`) и per-chat поля: чат хранит `presetId`, `thinkingEnabled`, `model`, `webSearch` (селекты в поповере «Параметры запроса» тулбара Composer — тулбар иконочный внутри карточки промпта, одинаков на любой ширине окна) и `context` (диалог «Контекст» — постоянный справочный текст чата). `system` собирается на фронте (`App.dispatchSend`): текст пресета (`lib/presets.presetText`) + выбранные материалы библиотеки контекстов (`lib/context-library.libraryContextBlocks` по `chat.libraryDocIds`) + контекст чата, и всё уходит в `send_to_claude(messages, chat_id, system, thinking, model, web_search)` при каждом запросе (Anthropic API stateless). Старые чаты без `presetId` → без препромпта; без `model` → дефолтная opus; без `thinkingEnabled` → true (как вёл себя старый код); без `webSearch`/`context` → false/"" — эти дефолты — протокол совместимости со старым chats.json. `Settings.fast_mode` → `speed:"fast"` + beta-заголовок `fast-mode-2026-02-01`, только для `claude-opus-4-8` (capabilities это не выражают). `Settings.chat_font_size` → CSS-переменная `--chat-font-size` (`applyChatFontSize`), масштабирует текст и код чата. `Settings.stt_language`/`stt_translate` — язык Whisper и перевод на английский (см. stt.rs). `Settings.screen_share_visible` — показывать окно при демонстрации экрана (см. Window chrome). `Settings.teleprompter_speed`/`teleprompter_font_size` — параметры телесуфлёра (клампы 10–150 px/с и 20–48 px в `settings.clamp` + `lib/teleprompter`), персистятся при закрытии суфлёра. `Settings.teleprompter_hotkey` (дефолт `F10`) — глобальный хоткей открытия/закрытия суфлёра. `Settings.teleprompter_resume` (дефолт `true`) — суфлёр открывается с сохранённой позиции скролла (если текст ответа тот же), иначе с начала. `Settings.window_width`/`window_height` — базовый логический размер окна (дефолт 960×680 — обязан совпадать с `tauri.conf.json`; клампы 300–1600×520–1100 в `settings.clamp` и `lib/window-size.ts` — менять синхронно; `minWidth` в conf ≤ нижнего клампа); применяется на старте (`apply_window_size_at_startup`) и при каждом изменении через `useWindowFrameSync` в App.tsx. `Settings.resize_step` — шаг хоткеев размера (настройка «Шаг изменения размера», кламп 1–200 как у `move_step`). `Settings.capture_device_uid` — UID устройства вывода для захвата (`""` = системный дефолт + автопересоздание тапа при его смене; см. capture.rs). `Settings.theme` — `"gray"` (дефолт, CSS-переменные `:root`) или `"black"` (оверрайды в `:root[data-theme="black"]`); применяется `applyTheme` (data-атрибут на documentElement) из `applyVisualSettings`, кламп неизвестных значений в gray — в `settings.clamp` и `applyTheme` синхронно. `Settings.scroll_step` — шаг скролла чата хоткеем ⌥↑/↓ (кламп 10–1000; обработчик `useHotkeyScroll` в AnswerPanel, document-level keydown с preventDefault — прыжок каретки по абзацам через Option+стрелки пожертвован, прецедент Cmd+стрелок). `Settings.buffer_enabled`/`buffer_seconds` — фоновый кольцевой буфер последних N секунд системного звука (кламп 4–10 с, дефолт 4; включён по умолчанию): звук непрерывно ресемплируется в 16 кГц и живёт только в RAM (`audio::RollingBuffer` внутри `capture::Shared`), при старте PTT-записи снимок буфера автоматически приклеивается к началу транскрипции (и в стриминговое тело Groq, и в аккумулятор сессии) — подхватывает сказанное до нажатия; выключение тумблера немедленно очищает буфер, на диск ничего не пишется; side-effects смены полей — `apply_buffer_settings_change` в `set_settings`, при пересоздании tap буфер начинается заново (потеря ≤10 с осознанна).
- **Модели — динамические, не хардкод.** Команда `list_models` (Rust `llm::list_models`, `GET /v1/models`, бесплатный) отдаёт модели аккаунта с выжимкой capabilities (`ModelInfo {id, displayName, adaptive, alwaysThinks, codeExec, maxInputTokens}`; `maxInputTokens` — из поля `max_input_tokens` ответа `/v1/models`, у фолбэк-моделей 0 = «неизвестно»); кэш в `App.models`, первичный фетч на старте, фронт берёт через `useModels` (фолбэк — `lib/models.FALLBACK_MODELS`). Поле `thinking` собирает `llm::thinking_value` по capabilities: вкл → `adaptive` где поддержан; выкл → явный `{"type":"disabled"}` (на Sonnet 5 «опустить поле» = adaptive!); haiku (adaptive не поддержан) и Fable/Mythos («думают всегда» — единственное исключение по имени, capabilities этого не выражают) → поле не отправляется. Селект thinking в Composer блокируется через `lib/models.thinkingLocked`. Веб-поиск (`llm::web_search_value`) — server-side tool `web_search_20260209` в `tools` (Anthropic ищет сам, внутри того же стрима — клиентского tool-loop нет); моделям без code execution (haiku, `capabilities.code_execution`) обязателен `allowed_callers:["direct"]`, иначе API отвергает запрос (проверено живыми пробами — сами tool-версии в capabilities не выражены).

## Frontend architecture (`src/`)

Strict layering — keep each layer's responsibility intact:

- **`src/ipc/`** — the **only** place that imports `@tauri-apps/api`. `commands.ts` (typed `invoke`), `events.ts` (`onEvent`), `types.ts`, `env.ts` (`isTauri`). Every command/event no-ops in the browser so the UI runs without a backend.
- **`src/lib/`** — framework-free pure logic with unit tests: `api-keys.ts` (`missingApiKeys`/`missingKeysNotice` — какие ключи API отсутствуют и текст баннера), `composer.ts` (attachment limit/downscale, `Attachment` type), `chats.ts` (chat model, `CHAT_LIMIT`, serialize/deserialize), `models.ts` (`ModelInfo`, `FALLBACK_MODELS`, `thinkingLocked`), `hotkey-capture.ts` (`hotkeyFromEvent`, `conflictsWithTyping`), `window-controls.ts` (`moveDelta`/`applyOpacity`/`applyChatFontSize`), `stream-markdown.ts` (`splitStableTail` — деление стрима на стабильный префикс/хвост для мемоизации markdown-парса; авторост поля промпта — JS-хук `usePromptAutosize` в Composer через scrollHeight + ResizeObserver, `field-sizing: content` в WKWebView не работает), `teleprompter.ts` (`toReadingText` markdown→проза, `advanceOffset` скролл-мат, `clampSpeed`/`clampFont`).
- **`src/hooks/`** — one hook per contract slice (`useClaudeStream`, `useChats`, `useModels`, `useSettings`, `useRecorder`, `useTranscription`, `useWindowControls`, `usePttSuspend`). `useChats` owns the chat list, per-chat drafts/attachments, and disk persistence. Hooks depend on `ipc`, never on `@tauri-apps` directly; tested with `renderHook` + `vi.mock("@/ipc/...")`.
- **`src/components/`** — presentational, built on shadcn/ui primitives in `src/components/ui/` (run `npx shadcn@latest add <name>` to add more). `App.tsx` composes hooks + components.

Stack: React 19 + Vite + Tailwind v4 (CSS-first `@theme` tokens in `src/index.css`, gray + oxblood dark theme, dark-only) + react-markdown + rehype-highlight. Path alias `@` → `src`. **Правило палитры: primary (окс-красный) НЕ используется как цвет текста** (заголовки секций, ссылки, бейджи, чипы — нейтральные `text-foreground/*`); primary допустим только для индикаторов (точки, эквалайзер, маркеры списков, подчёркивание активного таба), заливок кнопок и `destructive`-ошибок.

**Подсветка кода:** rehype-highlight в `AnswerPanel` (`REHYPE_PLUGINS`); палитра токенов — в `index.css`. Инвариант: `html` в `plainText` — чип превью (`HtmlBlockChip` через `makePre`) требует, чтобы children код-элемента остались **сырой строкой**; подсветка превратила бы их в массив span'ов и молча сломала чип. Во время стрима markdown-чанки мемоизированы (`MarkdownChunk` + `splitStableTail`) — история и завершённые блоки не перепарсиваются на каждый флаш дельт. **Скролл-к-низу при переключении чата — синхронно ДО пейнта** (`useLayoutEffect` в AnswerPanel, а не `useEffect`): иначе браузер успевает показать кадр со старой позицией → видимый «полёт сверху вниз». `content-visibility` на сообщениях НЕ используется намеренно: он делал `scrollHeight` оценочным (офскрин-элементы схлопнуты в intrinsic-size), из-за чего пре-пейнт-скролл промахивался мимо низа и приходилось добивать rAF-циклом — костыль убран вместе с ним. Для реально огромной истории правильный инструмент — виртуализация (virtua), а не content-visibility (он ломает точность `scrollHeight`). `splitStableTail` режет стрим на префикс/хвост ТОЛЬКО по границе абзаца `\n\n` вне fenced-код-блока (признак «внутри fence» — нечётное число fence-маркеров, backtick- или tilde-, в префиксе): незакрытый fence сломал бы рендер обеих половин.

**Browser mock:** `isTauri()` (checks `__TAURI_INTERNALS__`) gates all backend calls; outside Tauri the app renders with demo data, so `vite preview` is the way to visually iterate without building the `.app`.

## Rust backend (`src-tauri/src/`)

`lib.rs` is the glue: `App` state, all `#[tauri::command]`s, event emission, the recording pipeline, and the global-hotkey wiring. The domain modules are pure and unit-tested:

- `audio.rs` — downmix → resample (rubato, 48k→16k) → WAV (hound); RMS silence gate. `StreamResampler` — инкрементальный ресемплинг для стриминга (батчевый `resample_to_16k` идёт через него же — один код-путь; к тому же rubato `process_all_into_buffer` дублирует первые `output_delay` фреймов, инкрементальный путь от этого бага свободен); параметры sinc намеренно «речевые» (`sinc_len=32`) — студийный 128 для 16кГц-Whisper уже отвергнут (~4x CPU впустую); `wav_header_streaming` (размеры 0xFFFFFFFF) + `f32_to_i16le_bytes` для тела стриминговой загрузки.
- `capture.rs` — system-audio capture via **Core Audio process tap** (`cidre`). The risky native piece. RT-колбэк пишет в lock-free ring buffer (`ringbuf`, без мьютексов/аллокаций); поток-консьюмер на лету даунмиксит+ресемплит в 16кГц, копит буфер и отдаёт чанки в опциональный `ChunkSink` (его дроп = EOF для стриминга). `stop()` возвращает готовый 16кГц-моно. Флагом `recording` управляет только консьюмер (протокол `Session` + `stop_requested` исключает гонку «stop до пробуждения консьюмера»); порядок остановки обязателен: сначала `recording=false`, потом дрен хвоста кольца. Порядок полей `SystemAudioCapture` — это порядок drop (`_started` → `_tap` → `_ctx`; на `_ctx` ссылается C-колбэк): перестановка = use-after-free в IO-потоке. `unsafe impl Send` отключает автопроверку компилятора — при добавлении полей пересматривать вручную; доступ — только под Mutex. Отказ TCC на запись системного звука не различим по коду ошибки: Core Audio отдаёт `kAudioHardwareIllegalOperationError` ('!hog'), и именно он маппится в PermissionDenied — «более точного» кода нет; при отказе в state кладётся `None` (UI видит через `capture_available`: баннер + секция прав в стартовой модалке `MissingKeysDialog` — «Запросить» зовёт `request_audio_capture_permission`, т.е. пересоздание тапа, что триггерит TCC-промпт при статусе «не спрошено»; «Настройки macOS» — `open_audio_permission_settings`; `NSAudioCaptureUsageDescription` живёт в `src-tauri/Info.plist` и встраивается и в dev-бинарь — без него macOS не спрашивает, а молча отказывает). Главный sub-device приватного aggregate — устройство вывода как clock source (`Settings.capture_device_uid`, `""` = системный дефолт через `resolve_output_device`; несуществующий uid молча падает на дефолт); убирать `sub_device_list` «за ненадобностью» нельзя. **Tap привязан к устройству на момент создания** — сменился вывод → тап отдаёт нули («Тишина»); поэтому lib.rs слушает `kAudioHardwarePropertyDefaultOutputDevice` (`install_default_output_device_listener`, колбэк деферится в async runtime) и пересоздаёт капчер при смене дефолта (только когда uid=""), при смене `capture_device_uid` в set_settings, а если рекордер занят — лениво на следующем PTT через флаг `capture_rebuild_pending`. Список устройств для UI — `list_audio_output_devices` (`capture::list_output_devices`, фильтр по наличию output ASBD), селект в настройках («Распознавание речи»). Manual acceptance via `examples/record5s.rs`; живой смоук стриминга в Groq — `examples/stream_smoke.rs`. Режим непрерывной буферизации: `set_buffering(true)` переводит консьюмер в цикл `run_buffering` с долгоживущим ресемплером (`io_proc` пропускает семплы по `recording || buffering`), каждый 16кГц-чанк уходит в `audio::RollingBuffer` под мьютексом; PTT-сессия при включённом буфере обслуживается тем же циклом: `take_pending_session` сбрасывает снимок буфера в аккумулятор и `ChunkSink` ДО живых чанков (преролл), rolling-лок берётся только после отпускания session-лока (session- и rolling-локи никогда не держатся одновременно), `finish()` ресемплера не зовётся (потеря хвоста ~20 мс речи при отпускании осознанна); при выключенном буфере путь консьюмера прежний; буферизованная сессия тоже ведёт флаг `recording` (`take_pending_session` ставит, наблюдение стопа и финализация снимают) — io_proc-гейт остаётся корректным при выключении тумблера посреди записи, а выход из режима буферизации чистит rolling на стороне консьюмера. Сигнатура — `SystemAudioCapture::new(uid, buffer_secs)`.
- `stt.rs` — `GroqStt` (whisper-large-v3-turbo; язык из `Settings.stt_language`, "" = автоопределение; `stt_translate` → эндпоинт `/audio/translations` + модель whisper-large-v3 — turbo переводов не умеет, поле language не отправляется), error mapping; `transcribe_stream` — multipart с телом-стримом (chunked, длина неизвестна; Groq это принимает — проверено живым смоуком); его общий таймаут намеренно щедрый (11 мин): тело живёт всю запись (до 10 мин), обычный 60-секундный таймаут оборвал бы стрим. Клиент пересоздаётся в `set_settings` при смене ключа/языка/перевода.
- `llm.rs` — Anthropic request body (image blocks; поле `thinking` готовит `thinking_value`, элемент `tools` веб-поиска — `web_search_value`, оба по capabilities модели; prompt-cache брейкпоинты на system и последнем сообщении; пустые сообщения выбрасываются из истории — API отвергает пустой content; `speed:"fast"` при fast_mode+opus-4-8), incremental `SseParser` (use `feed_bytes` for chunked UTF-8; server_tool_use-события веб-поиска игнорируются — до UI доходят только текстовые дельты), streaming client with cancellation; тела ошибок API пробрасываются в UI (`error.message`, не голый HTTP-код). Диагностика тел запросов против живого API — `examples/llm_smoke.rs`.
- **Все reqwest-клиенты шлют `User-Agent`** (`llm::APP_USER_AGENT` = `AudioSystem/<версия>`; llm, stt, access): reqwest без UA попадает под Cloudflare Browser Integrity Check на прокси → интермиттентные `403 error code: 1010`; тела не-JSON ошибок теперь включаются в сообщение (`api_error_message` — сниппет до 120 симв).
- **Прокси `itech-relay` (Cloudflare Worker, репо `screenfriskofficial/itech-relay`).** Правки воркера деплоятся отдельно: `wrangler login` (интерактивно) → `wrangler deploy` (node ≥22, напр. `PATH=/opt/homebrew/opt/node@25/bin:$PATH`). Известные инварианты воркера: (1) **Рейт-лимитов на запросы нет** (снято 2026-07-21): лиз параллельности удалён (чаты приложения стримят одновременно), суточные капы = `MAX_SAFE_INTEGER` — учёт `usage_daily` продолжает вестись для `/admin/usage`, но никогда не отсекает; клампы не ниже клиентских значений (`max_tokens` 64000, `web_search max_uses` 10; клиент шлёт 64000/5). Остались только: IP-лимит на `/v1/redeem`, лимиты размера тела (LLM 32 МБ, STT 26 МБ) и allowlist роутов/моделей. upstream-`fetch` ОБЯЗАН иметь `signal: request.signal` — иначе при отмене клиента (кнопка «Стоп») воркер дочитывает генерацию до конца и владелец платит за полный ответ. (2) `/v1/messages/count_tokens` маршрутизируется явной веткой (без дебита) — нужен для индикатора заполненности контекста. Оба reqwest-клиента (`stt`/`llm`) создаются один раз на весь рантайм, держат пул «вечно тёплым» (`http2_keep_alive_*`, `pool_idle_timeout(None)`) и имеют `warm_up()`; прогрев зовётся на старте приложения и на нажатии PTT (Anthropic; Groq не греется — стриминговый запрос уходит сразу). В командах клиент клонируется из state (clone шарит Arc пула) — в том числе чтобы не держать MutexGuard через `.await`. Перф-тайминги пишутся в stderr с префиксом `[perf]`.
- **Стриминговая транскрипция.** На нажатии PTT `on_ptt_pressed` открывает запрос к Groq (`App.stt_stream`), тело наполняется 16кГц-чанками через sink капчера; на отпускании `finish_transcribe` ждёт уже идущий запрос («отпустил → текст» ≈ инференс + RTT). Отмена (Esc/тишина/короткая запись) — `cancel_stt_stream`; порядок при отмене записи обязателен: сначала `cancel_stt_stream`, только потом `capture.stop()`. При переполнении канала sink помечает стрим `broken`; любой сбой стрима (кроме `BadApiKey`) → фолбэк на классический `transcribe` по накопленному буферу — фича деградирует, но не ломает распознавание. На фронте `transcript-ready` ДОПИСЫВАЕТСЯ к черновику (`lib/composer.appendTranscript`), а не заменяет его; при `auto_send` уходит объединённый текст.
- `state.rs` — recorder FSM (`Idle → Recording → Transcribing → Idle`); min 0.3s / max 10min, Esc cancel.
- `settings.rs` — JSON at `~/Library/Application Support/com.audioservice.helper/settings.json`, written atomically with `0600`.
- `update.rs` — автообновление через `tauri-plugin-updater`: `check()` (манифест `latest.json` из публичного репо `screenfriskofficial/harpyhare-releases`, endpoint/pubkey в `tauri.conf.json`; `ITECH_UPDATE_ENDPOINT` подменяет endpoint для тестов), `install()` (скачивание подписанного `.app.tar.gz`, minisign-проверка, замена бандла, `app.restart()`; перед restart — пауза 300мс, чтобы webview дорисовал «Перезапуск…», restart убивает процесс немедленно), фоновая автопроверка (старт + каждые 6 ч; в debug — только при заданном `ITECH_UPDATE_ENDPOINT`). `update-available` от автопроверки может прийти во время идущей установки — фронт (`useUpdater`) не даёт ему перебить статусы downloading/restarting. Найденный `Update` живёт в `App.pending_update` между check и install; повторный install блокирует `App.update_installing`. Прогресс троттлится `progress_step` (по смене целого процента) — как коалесинг `llm-delta`. Ошибка install уходит реджектом команды (отдельного события нет); `Settings.skipped_version` глушит только автобейдж, не ручную проверку. Релиз-пайплайн — `scripts/release.mjs` (ключ подписи `~/.tauri/itech.key`, **бэкапить**; см. README «Релиз»).
- `hotkey.rs` — push-to-talk registration + глобальный toggle-хоткей скрытия/показа окна (`register_toggle` → `on_toggle_visibility`) + глобальный хоткей суфлёра (`register_teleprompter` → `on_toggle_teleprompter`: эмитит `toggle-teleprompter`, фронт переключает оверлей — работает, даже когда HUD не в фокусе, окно always-on-top видно); `parse_hotkey` is the only unit-tested function here. Обработчики деферятся (`defer`) — инвариант реестра плагина. Все три хоткея регистрируются в `register_startup_hotkeys` и перерегистрируются в `set_settings` при смене.

## Non-obvious invariants (do not break these)

- **Чаты независимы и параллельны.** Источник истины — фронт (`useChats`: `Chat[]` + `activeId`); Rust хранит чаты как непрозрачную JSON-строку в `chats.json` (атомарно, `0600`, модуль `chats.rs`, команды `load_chats`/`save_chats`). `send_to_claude(messages, chat_id, system, thinking, model, web_search)` шлёт всю историю чата; отмена по-чатная через `Mutex<HashMap<chat_id, CancellationToken>>`. Картинки в `chats.json` не сохраняются (стрипаются в `serializeChats`); текстовый `context` чата — сохраняется; `libraryDocIds` (выбор материалов библиотеки) — сохраняется, старые чаты без поля → `[]`. **Библиотека контекстов** — отдельный файл `context-library.json` (тот же паттерн, что chats.json: Rust хранит непрозрачный JSON через `chats::load/save`, команды `load_context_library`/`save_context_library`; модель и (де)сериализация — `lib/context-library.ts`, битые `folderId` чинятся в корень, тексты клампятся `DOC_TEXT_LIMIT_CHARS`; хук `useContextLibrary` — дебаунс-сохранение 500мс после первичной загрузки, тот же инвариант «не сохранять до загрузки»). UI — вкладка «Контексты» в настройках (`ContextLibraryPanel`, правки применяются сразу, мимо draft/Сохранить диалога); выбор материалов в чате — диалог «Контекст» Composer (чекбоксы + свой текст). Импорт файлов: пикер (`input type=file`) и **drag-and-drop из Finder** — HTML5-drop для файлов ОС в Tauri НЕ работает (webview перехватывает), используется `getCurrentWebview().onDragDropEvent` (обёртка `ipc/events.onFileDrop`, физпиксели → CSS через devicePixelRatio), папка-цель — `elementFromPoint` по атрибуту `data-drop-folder`. Поддерживаемые типы — **.md/.markdown/.txt и .pdf** (`context_import.rs` диспетчеризует по расширению): текст читается `read_to_string` (лимит 1 МБ), PDF — `pdf-extract::extract_text_from_mem` в `catch_unwind` (битый PDF не должен ронять процесс; лимит 20 МБ), затем `normalize_extracted_text` (CR/form-feed → `\n`, схлопывание пустых строк, trim); пустой результат = скан без текстового слоя → ошибка `ERR_PDF_NO_TEXT` (OCR нет, только текстовый слой). Извлечённый текст всё равно клампится `DOC_TEXT_LIMIT_CHARS`. Пути к файлам: drop даёт реальный путь → `read_context_import_file(path)`; у пикера в WKWebView реального пути нет (`File.text()` для текста, а PDF читается `File.arrayBuffer()` → `lib/base64.arrayBufferToBase64` → `read_context_pdf_bytes(dataBase64)`). Обе команды парсят в `tokio::spawn_blocking` (парс 20 МБ не блокирует рантайм). В браузерном моке PDF недоступен (нет бэкенда) → сообщение об ошибке; текст — обычный HTML5 drop / File.text(). Перенос материалов между папками — кастомный pointer-драг (`useDocDrag`: mousedown+порог 5px → mousemove → `moveDoc` по `data-drop-folder` под курсором), НЕ HTML5 draggable — внутристраничный HTML5-dnd в Tauri-вебвью ненадёжен. Дебаунс-сохранение на диск (500мс) включается только после завершения первичной загрузки (флаг `loaded` в `useChats`) — иначе стартовое пустое состояние перезаписало бы сохранённые чаты. Лимит — `CHAT_LIMIT = 6`.
- **PTT обязан работать при фокусе в поле промпта.** `usePttSuspend` глушит PTT при фокусе в текстовых полях ТОЛЬКО для хоткеев, конфликтующих с печатью (`conflictsWithTyping`: одиночная буква/цифра, в т.ч. с Shift). F-клавиши и комбинации с Cmd/Ctrl/Alt не глушатся никогда — не возвращай безусловную заглушку.
- **Hotkey handlers must defer all work.** `tauri-plugin-global-shortcut` invokes the handler while holding its registry mutex; doing register/unregister synchronously inside (e.g. registering Esc) is a re-entrant deadlock that hard-freezes the app. `hotkey.rs` wraps handlers in `defer()` (spawns onto the async runtime). The same applies to anything a handler triggers.
- **Window manipulation goes through Rust commands, not JS.** `move_window_by`, `set_window_size`, `close_app`, `hide_main_window` are Rust commands. The JS `getCurrentWindow().setSize()` path silently fails because the window capabilities in `src-tauri/capabilities/default.json` grant `set-position`/`show`/`hide`/`start-dragging` but **not** `set-size`. Add any new window capability there if you must call from JS; otherwise prefer a Rust command. `set_window_size` tweens (ease-out) width+height on a background thread, dispatching each frame via `run_on_main_thread`, with a `resize_gen` generation guard; верхний край Y фиксирован (рост вниз), целевой `x` — текущий, только клампится в границы монитора (`anchored_target_x` → `window_geom::clamp_window_x`): окно растёт вправо на месте и сдвигается влево лишь упёршись в правый край (не уедет за экран); центрирования НЕТ намеренно — оно раздражало при хоткей-ресайзе и открытии превью; ранний выход — по эпсилону размеров, вызов с тем же размером — полный no-op. Перетаскивание окна ЛКМ — **явным** `getCurrentWindow().startDragging()` (`startWindowDrag` в `ipc/commands.ts`), а НЕ через `data-tauri-drag-region`: атрибутная инъекция Tauri в этом фреймлесс+transparent окне не срабатывала. `useWindowDrag` вешает `onMouseDown` на шапку (StatusBar); футера-шпаргалки больше нет — справочник всех хоткеев живёт в поповере `HotkeysPopover` (иконка клавиатуры в шапке); данные — единый реестр `lib/hotkeys.hotkeyGroups(cfg)` (настраиваемые комбо приходят из Settings, при добавлении хоткея дополнять реестр, не разметку); табы чатов — номерные квадраты `ChatTabs` в шапке (скроллятся по горизонтали в узком окне; × по ховеру только на активном табе — у неактивных клик выбирает чат; переименование чатов удалено, поле `title` живёт в данных для совместимости chats.json; слева табы НЕ размещать — боковая рейка ломала симметрию чат-колонки и отвергнута); корневой `.app-shell` в App.tsx тоже стартует драг, но только при клике прямо по нему (`target === currentTarget` — верхний/боковые отступы `p-4` и зазор колонок; иначе клик по тексту чата ломал бы выделение). Драг стартует только для ЛКМ и только если `isDraggableChromeTarget` (клик не по интерактиву — селектор `button, a, input, textarea, select, [role='tab'], [data-no-drag]`), поэтому кнопки/табы остаются кликабельными, а клик по значку внутри кнопки (SVG, не HTMLElement) драг не стартует. Курсор над драг-зоной остаётся стрелкой (глобальный `cursor: default`) — осознанно. Кнопки окна в шапке — ghost-иконки (`WindowButton`): `X` → `close_app` (ховер краснеет), `Minus` → `hide_main_window` (возврат — глобальным toggle-хоткеем); один стиль с шестерёнкой настроек.
- **Cmd/Ctrl+стрелки двигают окно через нативный локальный NSEvent-монитор** (`install_move_keys_monitor` в lib.rs), который поглощает keyDown ДО WKWebView — иначе каретка прыгала бы по текстовому полю, а сдвиг окна ходил бы через IPC. JS-обработчик в `useWindowControls` эти события в Tauri не получает (остался для браузерного мока). С Shift те же стрелки меняют **размер** окна: монитор поглощает keyDown и эмитит `resize-key {dim, dir}`; фронт (`useWindowControls` → `useSettings.bumpWindowSize`) шагает `Settings.window_width/height` на `resize_step` с клампами из `lib/window-size.ts`, окно применяет `useWindowFrameSync`, персист — дебаунсом (как opacity). Полярность: ←/↑ меньше, →/↓ больше.
- **Указатель мыши никогда не прячется и не меняет форму.** WebKit при печати в текстовом поле просит спрятать указатель «до движения мыши» через `+[NSCursor setHiddenUntilMouseMoves:]` в UI-процессе; на старте (`disable_cursor_autohide_on_typing` в lib.rs) этот класс-метод свизлится в no-op — публичный objc-runtime API, детерминированный фикс. Пост-фактум `setHiddenUntilMouseMoves(false)` НЕ работает: скрытие приходит асинхронным IPC и гонку выигрывает (такая компенсация была в `move_window_by` и удалена как ненужная при свизлинге). Форма указателя — всегда стандартная стрелка: глобальный `cursor: default !important` в index.css намеренно подавляет I-beam/pointer/not-allowed во всех кейсах — не убирай.
- **`onEvent` uses a `live` flag** to pair subscribe/unsubscribe across the async `listen` promise — required for React StrictMode double-mount safety. `useClaudeStream` likewise cancels its pending rAF on unmount and gates late deltas after `stop`. Частичный ответ на `stop`/`llm-error` НЕ выбрасывается — уходит в историю через `onComplete` (дубля нет: `llm-done` отменённого стрима подавляется, чат уже снят с `active`). Буферы дельт и набор активных стримов живут в ref, а не в state: обработчики событий подписаны один раз и обязаны видеть свежие значения без переподписки — перенос в state/deps сломает роутинг дельт.
- **API keys: `.env` is a fallback only.** `lib.rs` setup reads `ANTHROPIC_API_KEY`/`GROQ_API_KEY` and applies them via `settings.apply_key_fallback` **only when** the corresponding settings.json field is empty (UI-saved keys win). `.env` is read from cwd and from `CARGO_MANIFEST_DIR/..` (so a Finder-launched `.app`, whose cwd is `/`, still finds the project `.env`). `.env` is gitignored. **Гейт «нет ключей» — на фронте** (`useMissingKeysGate` в App.tsx): `get_settings` отдаёт настройки уже с применённым `.env`-фолбэком, поэтому пустое поле на фронте = ключа нет нигде. Любой пустой ключ после загрузки настроек → модалка `MissingKeysDialog` (ссылки на консоли провайдеров через `open_external`, кнопка в настройки), баннер `WarningBanner` и дизейбл всех контролов Composer + блок `dispatchSend` (ref `sendBlockedRef` — глушит и Enter, и auto_send). В браузерном моке гейт выключен, чтобы демо оставалось рабочим; включается параметром `?nokeys` для визуальной итерации.
- **Коды доступа (прокси-режим).** Альтернатива своим ключам: пользователь вводит одноразовый код, команда `redeem_access_code` (`access.rs`) обменивает его на bearer-токен прокси-сервера (Cloudflare Worker, репо `itech-relay`, дизайн — `docs/superpowers/specs/2026-07-09-access-codes-proxy-design.md`) и кладёт в `Settings.access_token`. **Непустой `access_token` глушит ОБА ключа** — единый источник истины: `build_llm_client`/`build_stt_client` (`lib.rs`) строят клиент в прокси-режиме (`llm::AnthropicClient::for_proxy` — `Auth::ProxyBearer`, base_url прокси, `Authorization: Bearer` вместо `x-api-key`; STT — тот же bearer с другим base_url, код `stt.rs` не менялся), `apply_key_fallback` не подставляет `.env`, `missingApiKeys` возвращает `[]`. `rebuild_changed_api_clients` пересобирает ОБА клиента при смене `access_token`. Порядок в `apply_access_token`: сеть (redeem) → `save` на диск → rebuild → in-memory (ошибка save = reject, состояние не тронуто). Прокси-URL — константа `access::PROXY_BASE_URL`; env-override `ITECH_PROXY_ENDPOINT` — **только `cfg!(debug_assertions)` и только `https://`** (в релизе игнорируется — защита от редиректа токена/контента). Идемпотентность redeem — ключ из `crypto.randomUUID()` в `localStorage` (`redeem-idem:<норм.код>`), переиспользуется при повторе, чистится при успехе; `normalizeAccessCode` (`lib/access-code.ts`) обязана совпадать с серверной нормализацией. В прокси-режиме `require_ok_status` отдаёт тело `error.message` прокси на 401/403 (понятный текст «код недействителен»/«лимит исчерпан») вместо `BadApiKey`; STT-инвариант «401→BadApiKey без рефоллбэка» сохранён (Groq-путь не трогался).
- **Window chrome:** the `main` window is `transparent` + `decorations: false` (frameless, no native titlebar) + `alwaysOnTop` + `visibleOnAllWorkspaces` + `contentProtected`. Мышиный ресайз за невидимые края разрешён и синкается в настройки: `useNativeResizeSync` (App.tsx) слушает `onWindowResized` (`ipc/events.ts`, физпиксели → логические через scaleFactor), вычитает превью-экстру и пишет в `Settings.window_width/height` через `applyNativeWindowSize` (кламп + дебаунс-персист). Эхо программных твинов гасится guard-окном `PROGRAMMATIC_RESIZE_GUARD_MS` (600мс), которое `useWindowFrameSync` ставит ТОЛЬКО когда цель отличается от текущего нативного размера (`nativeSizeRef`) — иначе живой драг мышью сам себя заблокировал бы; гейт `readyRef` обязателен: событие до загрузки настроек иначе персистнуло бы DEFAULT_SETTINGS (пустые ключи!) на диск. `minWidth`/`minHeight` в conf совпадают с нижними клампами (300/520); верхние потолки — снап через кламп. Скругление окна продублировано нативно: `clip_native_window_corners` (lib.rs, setup) вешает `cornerRadius = WINDOW_CORNER_RADIUS_LOGICAL_PX` (22, обязан совпадать с `rounded-[22px]` шелла) + `masksToBounds` на слой contentView — иначе при твине ресайза WKWebView отстаёт на кадр и правые углы мигали бы острыми; CSS-радиус при этом не убирать (клип рисует форму, CSS — фон) (окно невидимо при демонстрации экрана; `Settings.screen_share_visible` снимает защиту через Rust `set_content_protected` — в setup и `set_settings`). `html/body` are transparent; the background is drawn by the root `.app-shell` via `--app-opacity` alpha (the opacity slider sets `--app-opacity` on `documentElement`; CSS-дефолт `--app-opacity: 0.9` в `index.css` обязан совпадать с дефолтом `window_opacity` в Settings — иначе до загрузки настроек окно рендерится с другой прозрачностью). Don't override `.bg-background` globally — shadcn's `DialogContent` uses it and would become translucent. Portaled content (dialog/select/tooltip) needs `body { color: var(--foreground) }` because it renders outside `.app-shell`. `DialogOverlay` (бэкдроп) обязан быть `rounded-[22px]` под радиус окна: окно прозрачное+фреймлесс, `fixed inset-0` без скругления залил бы угловые треугольники `bg-black/50` и они торчали бы острыми за скруглением. Модалки (`DialogContent`) НЕ используют `overflow-hidden`: в WKWebView `overflow:hidden`+`border-radius` на `transform`-элементе (диалог центрируется через `translate`) даёт острые углы; собственный фон радиус и так уважает, контент внутри `p-6` до углов не достаёт. HTML-превью ответов рендерится встроенной панелью `PreviewPanel` (правая колонка того же окна). Контент грузится с отдельного origin `preview://localhost` (кастомная схема `register_uri_scheme_protocol("preview", …)` в `lib.rs`, отдаёт `App.preview_html`, заполняемый командой `set_preview_html`) в `<iframe src sandbox="allow-scripts allow-same-origin">` — `localStorage`/сеть работают, но cross-origin к `tauri://localhost` + отсутствие capability на `preview://` изолируют превью от IPC и ключей. Нонс в `src` iframe'а (`preview://localhost/?v=N`) обязателен: заставляет WKWebView перезагрузить iframe даже при том же HTML и гасит гонку быстрых открытий (устаревший ответ `setPreviewHtml` игнорируется). Вне Tauri панель использует `srcDoc`-фолбэк. Открытие расширяет окно на месте через `useWindowFrameSync` (`set_window_size`). **Телесуфлёр** (`Teleprompter`, оверлей `absolute inset-0` над `.app-shell`) — крупный центрированный текст ответа (`toReadingText` снимает markdown), плавный автоскролл через один rAF-цикл (скролл — программный `scrollTop` на `overflow-hidden`; смещение считает `advanceOffset` по dt, чтобы скорость не зависела от частоты кадров), маска-фейд по краям + фокус-полоса по центру («глаз в одной точке»). Контейнер — `overflow-y-auto` (ручной скролл колёсиком; `onScroll` синхронит `offsetRef`, чтобы автоскролл продолжал с новой позиции, а не прыгал назад). Space — пауза, Esc — закрыть. Позиция/скорость/шрифт персистятся на размонтировании (`onPersist` в cleanup — ловит и закрытие хоткеем): App хранит `{text, offset}` в ref и при повторном открытии восстанавливает offset, если `teleprompter_resume` и текст тот же. Текст — стриминговый `partial`, иначе последний ответ ассистента. **Левая (чат) колонка — деривированной фикс-ширины** (`chatColumnWidth = window_width − 2·SHELL_PADDING_PX` в App.tsx — симметрично по краям окна), НЕ `flex-1`: иначе при монтировании панели `flex-1` сжимал бы чат на каждом кадре твина (перевёрстка markdown → видимое дёрганье). Ширина меняется только дискретно по хоткею размера; во время твина превью колонка стабильна — панель просто клипается `overflow-hidden` пока окно узкое и проявляется по мере разъезда; чат не релэйаутится и главный поток свободен для твина.
- **Window height меняется только пользователем.** Высота задаётся `Settings.window_height` (хоткеи Cmd+Shift+↑/↓); UI-логика высоту не трогает. Ширина — та же база плюс превью: окно = `window_width` + `PREVIEW_EXTRA_WIDTH_PX` при открытом превью, всё через `useWindowFrameSync` → `set_window_size` (эффект гейтится `!settingsLoading`, иначе дефолт затёр бы персистнутый размер, применённый Rust'ом на старте).
- **macOS only.** Capture relies on Core Audio process taps (macOS 14.2+); only `decorations: false` for the main window, `0600` perms, `open(1)` for external links (`open_external` пропускает только `http://`/`https://` — намеренная защита от `file://`/`smb://`), etc.
- **Имя процесса — «Audio System» (сборочно, стелс), бренд `harpyhare.ai` — только подпись в UI.** `productName` + `mainBinaryName` + window `title` = `Audio System`, identifier = `com.audioservice.helper` (`tauri.conf.json`) → `CFBundleName`, исполняемый файл (`Contents/MacOS/Audio System`, т.е. `ps`/`proc_name`/Activity Monitor/меню-бар) и метаданные окна (`CGWindowList` owner+title) единообразно показывают «Audio System»; бренд `harpyhare.ai` (`lib/brand.BRAND_NAME`) выводится только внутри приложения (подпись в настройках — её видит лишь пользователь). Рантайм-тоггла имени НЕТ (заголовок и процесс всегда «Audio System» — метаданные бренд не палят). Осознанный потолок: `contentProtected` скрывает пиксели окна из захвата, но НЕ факт присутствия — процесс и окно (`CGWindowListCopyWindowInfo`) перечисляются всегда; от выделенного детектора на той же машине скрыться нельзя. Имперсонация системных процессов (`com.apple.*`) намеренно НЕ используется: ad-hoc-подпись + чужой namespace — сама по себе сигнатура фейка и ломает TCC/нотаризацию. Артефакты сборки (`Audio System.app.tar.gz`, dmg) называются с пробелом (Tauri берёт `productName` дословно); в `release.mjs` загружаемый ассет и URL в `latest.json` используют ASCII-слаг `AudioSystem` — GitHub заменяет пробелы на точки в именах ассетов и сломал бы ссылку апдейтера.
